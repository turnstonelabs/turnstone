These localhost URLs work only from the server pods, so the console's own
status row for such a server, and the dialog's connection test, show an error;
save without the test. That is expected: coordinators run in the console and
have no node filesystem.

Where the image can require a bearer token, register the server with Static
headers (Authorization: Bearer ...). With No authorization, anything in the pod
can call it, the model's shell included, and a sidecar that listens on all
interfaces answers any pod in the cluster at the pod IP unless a NetworkPolicy
blocks it.
